# NotesMate 编辑器验收矩阵

对应 [EditorSpec.md](EditorSpec.md) 与 [EditorDesign.md](EditorDesign.md)。D1–D12 已写入规范 §11。本文件保留完整验收预期；2026-09-20 的执行记录、自动化覆盖和真机待验项见 [EditorAcceptanceResults.md](EditorAcceptanceResults.md)，不能将矩阵本身视为通过记录。

## 1. 测试组织

测试分为三个必要层次，复用同一组操作序列和模型 fixtures。

| 层次 | 验证对象 | 验收内容 |
|---|---|---|
| Core 单元/性质测试 | Document、Reducer、PositionMap、TriggerEngine、ListResolver、Exporter | 状态转换、Unicode 范围、编号、HTML 结构、撤销前后快照 |
| AppKit 集成测试 | 真实 NSTextView/TextKit、UndoManager、NSPasteboard 测试实例 | 原生 delta、typing 属性、布局、selection、粘贴来源和历史分组 |
| 真机交互 | 实际中文输入法、窗口、系统备忘录 | 候选窗定位、快捷键分派、排水区点击/拖选、缩放、最终 Notes 输出 |

测试 fixture 至少记录：初始文档、初始选区、输入来源、事件序列、最终段落/marks、选区、输入意图、编号、HTML、undo/redo 后状态。视觉断言以相对于正文起点的坐标为主，避免把系统字体抗锯齿差异当作语义失败。

Swift Package 测试 target 覆盖 Core、AppKit 集成和持久化；Xcode 工程保留应用 target，不应把 `xcodebuild build` 当成这些测试已执行。真机 IME 不能由直接调用 `insertText` 的测试替代。

## 2. 文档和范围

| ID | 操作/输入 | 预期 |
|---|---|---|
| M01 | 初始空编辑器 | 一个空 body 节点；投影长度 0；selection 合法 |
| M02 | 空文档转列表 → 输入 → 删光文字 | 同一个列表节点继续存在，不能自动变正文 |
| M03 | `a` → Enter → 文末列表按钮 | 最后一个空段成为列表；前面的 a 不受影响 |
| M04 | 光标在 `a\n` 的 EOF | 映射到末尾零长度段落，不能落到 a 段 |
| M05 | 单字符列表 `a` 按 Enter | 按非空项续排，不能因 paragraphRange.length == 1 退出 |
| M06 | 附件段插入（含列表项内任意落点） | 图片段恒为正文、独立成行；属于非空段；Enter 后续为正文 |
| M07 | 含 emoji、组合音符、中文的选区和删除 | 不拆代理对、组合字符或附件；UTF-16 范围正确 |
| M08 | 跨段落选区结束于下一段 offset 0 | 按 D9 不误处理下一段 |
| M09 | 反向选择、拖选跨列表/标题/正文 | anchor/head 与被覆盖段落正确 |
| M10 | 全选替换、跨段 cut、默认 Delete 合并段落 | 结构无丢失；undo 恢复原段落 ID/类型/文本 |

## 3. 触发与输入格式

| ID | 操作/输入 | 预期 |
|---|---|---|
| T01 | 逐键输入 `# ` / `## ` / `### ` | 对应空标题节点；标记消失；光标留在正文起点 |
| T02 | `- ` / `* ` / `1. ` / `99. ` | 列表转换；有序起号均为 1 |
| T03 | 三反引号后输入空格 | 转代码行 |
| T04 | `#### ` / `0. ` / `100. ` / `> ` / `--- ` | 不转换，保留原文 |
| T05 | 非段首，或标记前有空格 | 不触发块级转换 |
| T06 | 在已有列表中输入标题/列表/代码块标记 | 不触发块级转换；原列表节点保持 |
| T07 | `**粗体**` / `__粗体__` / `*斜体*` / `_斜体_` / `~~删除~~` / 单反引号配对 | 对应 mark；两端标志删除 |
| T08 | 标志内容为空、首尾空白、内部含同标记符 | 不转换 |
| T09 | `abc_def_` | 开口前不符合边界，不转换 |
| T10 | 中文标点后输入合法配对 | 按 Unicode 标点正确识别 |
| T11 | 逐键输入 `**a**`，停在第一枚闭合星号时观察 | 不被单星号提前解释成斜体 |
| T12 | 行内转换后立即输入中文、英文、空格与 emoji | 新内容不继承刚刚生成的行内格式 |
| T13 | 转换后 selection 通知、布局刷新、窗口缩放，再继续输入 | 显式复位意图不被系统属性继承覆盖 |
| T14 | 工具栏主动开启粗体后连续键入 | 继续使用粗体；与自动转换后的复位区别明确 |
| T15 | Undo 恢复带标志文本 → 点击/重排布局 | 不自动重新转换 |
| T16 | 闭合标志替换一个选区，或系统一次提交多个字符 | 基于真实 replacementRange 和来源判定，无旧下标越界 |
| T17 | 代码区域输入配对、跨段配对、三连标记、`01.` | 按 D3/D5 固定预期 |
| T18 | 逐键输入 `- [ ]`；另纯文本粘贴同一串 | 按 D12 前者是普通列表及文字，后者整串保持文字；不产生 task 语义 |

## 9. 性质测试与最终门槛

针对根本风险增加少量性质测试，而非只复写实现逻辑：

- 对含中文、emoji、组合字符、附件和空段的随机文档，合法位置在模型与 UTF-16 范围间往返保持一致。
- 随机执行输入、删除、格式、列表升降级、换行和撤销序列；每一步至少一个段落、层级合法、selection 可定位、附件引用有效。
- 对可撤销事务执行 apply → undo → redo，文档/选区/输入意图恢复到对应值；派生编号与重算结果相同。
- 同一文档的局部投影结果与全量参考投影一致；不同增量编辑路径到达相同语义状态时导出相同 HTML。
- 任意用户文本均只作为文本进入 HTML，不能生成白名单外节点；粘贴和历史回放不调用触发器。

最终至少在 macOS 13 和当前支持的较新系统验证；测试系统、输入法、Xcode 版本和失败复现序列写入结果。长文档滚动/输入使用实测延迟发现问题，不在没有测量时承诺固定性能数字。

发布门槛仍是 Core、AppKit 和关键真机项目全部通过。当前开发版本已替换旧编辑路径，尚未完成的真机项目必须在发布前补验，详见执行结果。
